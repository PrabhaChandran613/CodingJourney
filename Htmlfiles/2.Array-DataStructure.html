Problem Statement: 22¶

Find Minimum and Maximum in an Array: Given an array arr, find the minimum and maximum elements in the array.
Input: An array arr[] of size n containing integers.
Output: A pair containing two elements: First → Minimum value, Second → Maximum value.
Constraints: 1 ≤ n ≤ 10^5, 1 ≤ arr[i] ≤ 10^9

Example 1:
Input:
arr = [3, 5, 1, 2, 4, 8]

Output:
(1, 8)

Explanation:
Minimum = 1, Maximum = 8.

Example 2:
Input:
arr = [7]

Output:
(7, 7)

Explanation:
Only one element in the array, so both min and max are the same.

Approach:

  1. Initialize min and max with the first element.
  2. Traverse the array: update min if the current element is smaller, update max if larger.
  3. Return the pair (min, max). If the array has one element, return it as both min and max.

Pseudocode/Algorithm:

  1. Initialize min = arr[0] and max = arr[0].
  2. For each element elem in arr: a. If elem < min, update min = elem. b. If elem > max, update max = elem.
  3. Return (min, max). Code:
```java
import javafx.util.Pair;

class Solution {
    public Pair<Integer, Integer> getMinMax(int[] arr) {
        // Basic validation
        if (arr == null || arr.length == 0) {
            throw new IllegalArgumentException("Array must not be null or empty.");
        }

        int min = arr[0];
        int max = arr[0];

        // Iterate through the array to find min and max
        for (int i = 1; i < arr.length; i++) {
            if (arr[i] < min) {
                min = arr[i];
            }
            if (arr[i] > max) {
                max = arr[i];
            }
        }

        // Return result as a Pair
        return new Pair<>(min, max);
    }
}

✅ Complexity Analysis

  • Time Complexity: $O(n)$ — where $n$ is the number of elements in the array. We traverse the array once.
  • Space Complexity: $O(1)$ — constant extra space used, not counting the output pair.

✅ Additional Notes

  • The function efficiently computes min and max in one pass, making it optimal for large arrays (up to $10^5$ elements).
  • For further optimization, a divide and conquer approach can reduce the number of comparisons to about $1.5n$, but the linear approach is usually sufficient and more readable.

import java.util.*;

public class GfG {
   public static int missingNum(int[] arr) {
        long n = arr.length + 1;
    
        // Calculate the sum of array elements
        long sum = 0;
        for (int i = 0; i < arr.length; i++) {
            sum += arr[i];
        }

        long expSum = n * (n + 1) / 2;

        return (int)(expSum - sum);

Problem Statement: 27¶

Find Repeating Number in Array: Given an array arr[] of size n, where each element is between 1 and n-1, find the repeating number in the array.

Example:

Input:
arr = [1, 3, 4, 2, 2]

Output:
2

Explanation:
The numbers should be from 1 to 4, but 2 appears twice.

Constraints:

  • (2 \leq n \leq 10^5)
  • (1 \leq arr[i] \leq n-1)
  • Exactly one number is repeated, possibly multiple times
  • Array size is n, but values range from 1 to n-1 (hence one repetition)

Goal:
Find the one repeating element in the array using O(n) time and O(1) space.

🧮 Flowchart / Diagram: (Not included)
The conceptual flowchart includes:

  1. Initialize slow and fast pointers
  2. Detect cycle using Floyd’s algorithm
  3. Reset slow to start and move both one step until they meet
  4. Meeting point is the repeating element

Note: The array has exactly one element that repeats. Approach: We can solve this problem efficiently by using Floyd's Tortoise and Hare Algorithm (Cycle detection in a linked list). This approach helps in detecting cycles without extra space.

Explanation of Approach:

  1. Cycle Detection Approach (Floyd's Algorithm):

    • We treat each number in the array as a "pointer" to another index in the array.
    • This transforms the problem into finding the cycle in the array, where the "tortoise" and "hare" pointers will eventually meet at the repeating element.

  2. Steps:

    • First, we initialize two pointers, slow and fast. Both pointers will traverse the array, but the fast pointer moves two steps at a time while the slow pointer moves one step at a time.
    • Eventually, the two pointers will meet at some point within the cycle. Then, to find the repeating number, we reset one pointer to the start and move both pointers one step at a time until they meet again at the entry point of the cycle, which is the repeating number.

Code:

public class Solution {

    // Function to find the repeating number
    static int findRepeatingNumber(int arr[]) {
        // Phase 1: Finding intersection point in the cycle
        int slow = arr[0];
        int fast = arr[0];

        // Loop to detect the cycle
        do {
            slow = arr[slow];
            fast = arr[arr[fast]];
        } while (slow != fast);

        // Phase 2: Find the entry point of the cycle (repeating number)
        slow = arr[0];
        while (slow != fast) {
            slow = arr[slow];
            fast = arr[fast];
        }

        return slow;  // This is the repeating number
    }

    // Main method to test the function
    public static void main(String[] args) {
        // Example array with a repeating number
        int arr[] = { 1, 3, 4, 2, 2 };

        // Call the function and print the result
        System.out.println("The repeating number is: " + findRepeatingNumber(arr));
    }
}

Time Complexity:

  • O(n) → Due to single traversal for cycle detection and another for locating the entry point.

Space Complexity:

  • O(1) → No extra space is used, making it very efficient.

Notes:

  • This method is preferable over hash maps or sorting because it preserves linear time and constant space.
  • The input structure is critical: values from 1 to n-1 and n elements, so at least one duplicate must exist.

Goal:

  • Traverse using mid
  • Swap based on value of arr[mid] and adjust pointers accordingly

Approach

The problem asks us to sort the array containing only 0s, 1s, and 2s. The ideal solution for this is the Dutch National Flag Problem, which can be solved efficiently in one pass using the three-pointer technique.

Algorithm:

  1. Initial Pointers:

    • We will use three pointers: low, mid, and high.
    • low: This pointer keeps track of the boundary for the 0s.
    • mid: This pointer is used to scan the array.
    • high: This pointer keeps track of the boundary for the 2s.

  2. Three-Way Partitioning:

    • The mid pointer starts from the beginning of the array and moves towards the end.
    • If the current element (arr[mid]) is 0, we swap it with the element at the low pointer, then increment both low and mid.
    • If the current element (arr[mid]) is 1, we simply increment the mid pointer.
    • If the current element (arr[mid]) is 2, we swap it with the element at the high pointer, and decrement the high pointer.

  3. Termination Condition:

    • The algorithm terminates when the mid pointer surpasses the high pointer.

This approach guarantees that the array is sorted in one pass and uses only constant extra space (i.e., no additional arrays or data structures).

Code:

class Solution {
    // Function to sort an array of 0s, 1s, and 2s
    public void sort012(int[] arr) {
        // code here
        int low=0,mid=0,high=arr.length - 1;
        while(mid<=high){
            if(arr[mid]==0){
               int temp=arr[low] ;
               arr[low]=arr[mid];
               arr[mid]=temp;
               low++;
               mid++;
            }
            else if(arr[mid]==1){
              mid++;  
            }
            else{
                int temp=arr[mid];
                arr[mid]=arr[high];
                arr[high]=temp;
                high--;
            }
        }
    }
}

Time Complexity:

  • O(n): The array is traversed once, and each element is processed at most once.

Space Complexity:

  • O(1): No extra space is used for sorting (constant space).

Notes:

  • This is a classic variation of the Dutch National Flag Problem.
  • It ensures a stable and in-place sorting with linear time.
  • The key idea is three-way partitioning using just pointer manipulation.

class Optimized3SumIndices {
    static List<List<Integer>> findTriplets(int[] arr) {
        int n = arr.length;
        List<List<Integer>> res = new ArrayList<>();

        // Create a list of pairs (value, original index)
        Pair[] pairArr = new Pair[n];
        for (int i = 0; i < n; i++) {
            pairArr[i] = new Pair(arr[i], i);
        }

        // Sort by value
        Arrays.sort(pairArr, Comparator.comparingInt(p -> p.value));

        // Loop to fix the first element
        for (int i = 0; i < n - 2; i++) {
            int left = i + 1;
            int right = n - 1;

            while (left < right) {
                int sum = pairArr[i].value + pairArr[left].value + pairArr[right].value;

                if (sum == 0) {
                    int idx1 = pairArr[i].index;
                    int idx2 = pairArr[left].index;
                    int idx3 = pairArr[right].index;

                    if (!res.contains(triplet)) {
                        res.add(triplet);
                    }

                    left++;
                    right--;
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }

        return res;

	{
		// compute the max value in the array
		// and create frequency array of size
		// max_val + 1.

		// frequencies. We have used an array
		// to keep remaining code simple.

			max_val = Math.max(max_val, arr[i]);
		int[] freq = new int[max_val + 1];
		for (int i = 0; i < n; i++)
			freq[arr[i]]++;

		int ans = 0; // stores the number of ways

		// Case 1: 0, 0, 0
		ans += freq[0] * (freq[0] - 1) * (freq[0] - 2) / 6;

		// Case 2: 0, x, x
		for (int i = 1; i <= max_val; i++)
			ans += freq[0] * freq[i] * (freq[i] - 1) / 2;

		// Case 3: x, x, 2*x
		for (int i = 1; 2 * i <= max_val; i++)
			ans += freq[i] * (freq[i] - 1) / 2 * freq[2 * i];

		// iterate through all pairs (x, y)
		for (int i = 1; i <= max_val; i++) {
			for (int j = i + 1; i + j <= max_val; j++)
				ans += freq[i] * freq[j] * freq[i + j];
		}

	}

import java.util.HashMap;

class Solution {
    public int longestSubarrayWithSumK(int[] arr, int k) {
        HashMap<Integer, Integer> prefixSumMap = new HashMap<>();
        int prefixSum = 0;
        int maxLength = 0;
        
        // Initialize the prefix sum map with 0 at index -1 to handle the case where the sum is exactly 'k' at the beginning.
        prefixSumMap.put(0, -1);
        
        for (int i = 0; i < arr.length; i++) {
            prefixSum += arr[i];
            
            // If prefixSum - k is found in the map, then we found a subarray that sums to k
            if (prefixSumMap.containsKey(prefixSum - k)) {
                maxLength = Math.max(maxLength, i - prefixSumMap.get(prefixSum - k));
            }
            
            // Store the current prefix sum with its index if it's not already in the map
            if (!prefixSumMap.containsKey(prefixSum)) {
                prefixSumMap.put(prefixSum, i);
            }
        }
        
        return maxLength;
    }
}

class Solution {
    static int countMerge(int arr[], int l, int m, int r) {
        int n1 = m - l + 1, n2 = r - m;
        int[] left = new int[n1];
        int[] right = new int[n2];

        for (int i = 0; i < n1; i++) {
            left[i] = arr[i + l];
        }
        for (int j = 0; j < n2; j++) {
            right[j] = arr[j + m + 1];
        }

        int res = 0;
        int i = 0, j = 0, k = l;
        while (i < n1 && j < n2) {
            if (left[i] <= right[j]) {
                arr[k++] = left[i++];
            } else {
                arr[k++] = right[j++];
                res += (n1 - i);
            }
        }

        while (i < n1) {
            arr[k++] = left[i++];
        }
        while (j < n2) {
            arr[k++] = right[j++];
        }
        return res;
    }

    static int countInv(int arr[], int l, int r) {
        int res = 0;
        if (l < r) {
            int m = (r + l) / 2;
            res += countInv(arr, l, m);
            res += countInv(arr, m + 1, r);
            res += countMerge(arr, l, m, r);
        }
        return res;
    }

    // Function to count inversions in the array.
    static int inversionCount(int arr[]) {
        return countInv(arr, 0, arr.length - 1);
    }
}

    • Explanation: Maximum product is from [6, -3, -10].

Goal of the code: To find the subarray that yields the maximum product.

Intuition:

  • Multiplying two negative numbers gives a positive product, so keeping track of both the maximum and minimum products at each index is critical.
  • If the current element is 0, the product must restart.
  • The product may become large again after zeros or negative numbers, hence dynamic tracking is necessary.

  • The array contains all negative numbers.
  • The array contains all zeros (maximum product is 0).

  • Does not require any sorting or nested loops.

Alternative Approaches:

  • Brute-force: Try all subarrays (O(n²) time), but inefficient for large arrays.
  • Divide and conquer: More complex and not better than Kadane’s style dynamic programming for this problem.

Approach: We can solve this problem using a dynamic programming approach that keeps track of the maximum and minimum products that can be obtained by a subarray ending at each index. The minimum product is necessary because a negative number multiplied by a negative number can yield a large positive product.

  1. Iterate through the array.
  2. At each step, update the maximum and minimum products ending at the current index.
  3. The result will be the maximum product found during the iteration.

Pseudocode/Algorithm:

class Solution {
    static int max(int a, int b, int c) {
        return Math.max(a, Math.max(b, c));
    }

    static int min(int a, int b, int c) {
        return Math.min(a, Math.min(b, c));
    }

    static int maxProduct(int[] arr) {
        int n = arr.length;

        // max product ending at the current index
        int currMax = arr[0];
        // min product ending at the current index
        int currMin = arr[0];
        // Initialize overall max product
        int maxProd = arr[0];

        for (int i = 1; i < n; i++) {
            int temp = max(arr[i], arr[i] * currMax, arr[i] * currMin);
            currMin = min(arr[i], arr[i] * currMax, arr[i] * currMin);
            currMax = temp;
            maxProd = Math.max(maxProd, currMax);
        }

        return maxProd;
    }

    public static void main(String[] args) {
        int[] arr = { -2, 6, -3, -10, 0, 2 };
        System.out.println(maxProduct(arr));
    }
}

Time and Space Complexity: Time Complexity: O(n), where n is the number of elements in the array. We iterate over the array once, and each operation inside the loop is O(1). Space Complexity: O(1), as we only use a constant amount of extra space for the variables currMax, currMin, and maxProd.

Additional Notes: This approach efficiently handles both positive and negative numbers, as well as 0, which is crucial when calculating the maximum product subarray.

    • Output: [1, 3, 2]
    • Explanation: Next permutation after [1, 2, 3] is [1, 3, 2].

  • Example 2:

    • Input: [3, 2, 1]
    • Output: [1, 2, 3]
    • Explanation: Last permutation; return the first one.

  • Example 3:

    • Input: [1, 1, 5]
    • Output: [1, 5, 1]
    • Explanation: Next greater permutation.

Goal of the Code:
Find the next lexicographically greater permutation of a given array, or the smallest permutation if no larger one exists.

Approach:

  1. Find the Pivot:

    • Traverse from the rightmost side to find the first decreasing element (arr[i] < arr[i+1]).
    • If no such element is found, reverse the array as it is the last permutation.

  2. Find the Rightmost Greater Element to Swap:

    • Traverse from the right again and find the smallest element greater than arr[pivot].
    • Swap them to move to the next lexicographical order.

  3. Reverse the Suffix (Right Part After Pivot):

    • Reverse the subarray after the pivot index to get the next permutation.

Pseudocode/Algorithm:

  1. Identify the pivot (rightmost element where arr[i] < arr[i+1]).
  2. If no pivot exists, reverse the entire array and return.
  3. Otherwise, find the rightmost element greater than arr[pivot].
  4. Swap arr[pivot] with this greater element.
  5. Reverse the suffix (elements to the right of the pivot).

Code Implementation (Java):

import java.io.BufferedReader;
import java.io.InputStreamReader;

class Solution {
    void nextPermutation(int[] arr) {
        int n = arr.length;
        int pivot = -1;

        // Step 1: Find the pivot (first decreasing element from right)
        for (int i = n - 2; i >= 0; i--) {
            if (arr[i] < arr[i + 1]) {
                pivot = i;
                break;
            }
        }

        // Step 2: If no pivot found, reverse the array
        if (pivot == -1) {
            reverse(arr, 0, n - 1);
            return;
        }

        // Step 3: Find the smallest element greater than pivot from the right
        for (int i = n - 1; i >= pivot; i--) {
            if (arr[i] > arr[pivot]) {
                swap(arr, i, pivot);
                break;
            }
        }

        // Step 4: Reverse the suffix after pivot
        reverse(arr, pivot + 1, n - 1);
    }

    private static void reverse(int[] arr, int start, int end) {
        while (start < end) {
            swap(arr, start++, end--);
        }
    }

    private static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

  • The function returns a list of integers (ArrayList<Integer>) containing all the prime numbers in ascending order.

  1. Initialize a boolean array arr[] of size N+1 and mark all values as true (indicating all numbers are initially prime).
  2. Iterate through numbers starting from 2 to √N, marking multiples as non-prime (false).
  3. Collect the remaining prime numbers (values still marked true).
  4. Return the list of prime numbers.

Algorithm (Pseudocode):

  1. Create a boolean array of size N+1 initialized to true.
  2. Set arr[0] and arr[1] to false (since 0 and 1 are not prime).
  3. For each number p from 2 to √N:
    • If arr[p] is true, mark all its multiples as false (starting from p²).
  4. Collect numbers that remain true (primes).
  5. Return the list of primes.

import java.util.*;

class Solution {
    static ArrayList<Integer> sieveOfEratosthenes(int N) {
        ArrayList<Integer> prime = new ArrayList<>();
        boolean arr[] = new boolean[N + 1];

        Arrays.fill(arr, true); // Initialize all as prime

        for (int p = 2; p * p <= N; p++) {
            if (arr[p]) { // If p is prime
                for (int i = p * p; i <= N; i += p) {
                    arr[i] = false; // Mark multiples as non-prime
                }
            }
        }

        for (int p = 2; p <= N; p++) {
            if (arr[p]) {
                prime.add(p); // Collect prime numbers
            }
        }

        return prime;
    }

    public static void main(String[] args) {
        int N = 30;
        System.out.println(sieveOfEratosthenes(N));
    }
}
